## Overview

Rudiment UI is an accessible React 19 component library. It's built on [React Aria](https://react-spectrum.adobe.com/react-aria/) for accessibility and styled with BEM classes and `--rudi-*` design-token custom properties. The published CSS contains no Tailwind and no reset, so it won't restyle the rest of your app.

You can install it as a package, or clone it as the starting point for your own design system.

## Intended audience

Rudiment UI is for teams that want a solid foundation they can customize for their brand. Instead of building a component library from scratch, you get:

- **Components** with built-in accessibility
- **Design tokens** that make theming straightforward, including dark mode support
- **Tests** that verify behavior and accessibility
- **Documentation** in Storybook, plus a machine-readable API reference for AI coding agents

## Use it as a package

1. Install it. `react` and `react-dom` 19 are peer dependencies.

   ```bash
   npm install rudiment-ui
   ```

2. Import the stylesheet once, at your app's entry point.

   ```js
   import 'rudiment-ui/styles'
   ```

3. Import components. Every export carries the `Rudi` prefix.

   ```jsx
   import { RudiButton, RudiInput, RudiStack } from 'rudiment-ui'
   ```

There's no provider to mount. Every export is marked `'use client'`, so you can import it directly from a Next.js App Router Server Component.

Step-by-step guides cover a new [Vite](?path=/docs/getting-started-installation-vite--docs) app and a [Next.js](?path=/docs/getting-started-installation-next-js--docs) App Router app, including theme setup and client-side routing.

## Customize it as a template

1. Clone the repository and install dependencies.

   ```bash
   npm install
   ```

2. Start Storybook.

   ```bash
   npm run dev
   ```

3. Customize design tokens:
   - `tokens/tokens.json` holds primitive values.
   - `tokens/semantic.json` holds theme-level decisions.
   - `tokens/components.json` holds per-component tokens.
   - `tokens/themes/<name>/` holds each theme's overrides.

4. Build the tokens.

   ```bash
   npm run build:tokens
   ```

## Themes

Switch themes with the theme picker in the Storybook toolbar, or set `data-theme` on any element.

- **Default:** don't set the attribute. There is no `light` value.
- **Built-in themes:** `dark`, `roomy`, `roomy-dark`, `soft`, `soft-dark`, `compressed` and `compressed-dark`.
- **`auto`:** follows the operating system's light or dark preference.

See [Theming](?path=/docs/getting-started-theme-theming--docs).

## Conventions worth knowing

- **`onPress`, not `onClick`.** Interactive components use React Aria press events, which cover mouse, touch and keyboard.
- **`onChange` receives a value**, not an event. For example, `RudiInput` passes a `string` and `RudiCheckbox` passes a `boolean`.
- **`label` is a required prop** on form fields, progress indicators and charts. It becomes the accessible name.
- **Icons are Iconify name strings**, such as `icon="mdi:close"`. You don't import icon components.
- **Layout spacing takes a named step**, such as `space="group"`. You set each step's value per breakpoint once, in CSS. A fixed step (`space={4}`) or any CSS length also works. See [Responsive Spacing](?path=/docs/getting-started-theme-responsive-spacing--docs).

## AI coding agents

The package ships an API reference generated from its TypeScript source and JSDoc, so it matches the installed version. Agents can query it through the [MCP server](?path=/docs/getting-started-ai-mcp-server--docs) or read it as [LLMs.txt](?path=/docs/getting-started-ai-llms-txt--docs) files.
