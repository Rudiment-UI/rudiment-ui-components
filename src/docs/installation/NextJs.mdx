# Install with Next.js

Set up Rudiment UI in a Next.js App Router app. For an existing app, start at step 2.

## 1. Create the app

```bash
npx create-next-app@latest my-app --typescript --app
cd my-app
```

## 2. Install Rudiment UI

`react` and `react-dom` 19 are peer dependencies, and Next.js 15 and later already install them. No `transpilePackages` entry is needed.

```bash
npm install rudiment-ui
```

## 3. Import the stylesheet

Import `rudiment-ui/styles` once, in the root layout. It holds every component's styles and the design tokens for all themes. The components don't import their own CSS, so nothing renders styled without this line.

Rudiment ships no reset and no Tailwind, so it works next to Tailwind or your own `globals.css`.

```tsx
// app/layout.tsx
import 'rudiment-ui/styles'
import './globals.css'

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  )
}
```

## 4. Use a component

Every export is a Client Component: the package starts with a `'use client'` directive. You can import components straight into a Server Component and pass them serializable props such as strings and numbers.

```tsx
// app/page.tsx (a Server Component)
import { RudiCenter, RudiHeading, RudiLink } from 'rudiment-ui'

export default function Page() {
  return (
    <RudiCenter maxWidth="40rem">
      <RudiHeading level={1}>Dashboard</RudiHeading>
      <RudiLink href="/settings">Settings</RudiLink>
    </RudiCenter>
  )
}
```

A Server Component can render a component but can't reach a part through it, so `<RudiCard.Header>` in a Server Component fails the build with "Element type is invalid". This applies to every component with parts: `RudiCard`, `RudiDialog`, `RudiDrawer`, `RudiAppShell`, `RudiFooter`, `RudiCover`, and `RudiKanbanBoard`. Render these in a `'use client'` file, as below.

Event handlers such as `onPress` and `onChange` are functions, which a Server Component can't pass. Put the interactive part in its own file that starts with `'use client'`:

```tsx
// app/greeting.tsx
'use client'

import { useState } from 'react'
import { RudiButton, RudiInput, RudiStack } from 'rudiment-ui'

export function Greeting() {
  const [name, setName] = useState('')

  return (
    <RudiStack>
      <RudiInput label="Your name" value={name} onChange={setName} />
      <RudiButton onPress={() => alert(`Hello, ${name || 'there'}`)}>Say hello</RudiButton>
    </RudiStack>
  )
}
```

## 5. Pick a theme (optional)

With no attribute, the app uses the default light theme. Set `data-theme` on `<html>` in the root layout to use another one. `auto` follows the operating system's light or dark preference in CSS alone, so the server and client render the same markup and there's no hydration mismatch.

```tsx
<html lang="en" data-theme="auto">
```

See [Theming](?path=/docs/getting-started-theme-theming--docs) for the full list and for scoping a theme to part of the page.

## 6. Connect the router (optional)

`RudiLink`, `RudiNavItem` and `RudiBreadcrumb` render ordinary links, so each click reloads the page. To navigate client-side, pass the App Router's `router.push` to `RudiRouterProvider` in a small Client Component:

```tsx
// app/providers.tsx
'use client'

import { useRouter } from 'next/navigation'
import { RudiRouterProvider } from 'rudiment-ui'

export function Providers({ children }: { children: React.ReactNode }) {
  const router = useRouter()
  return <RudiRouterProvider navigate={router.push}>{children}</RudiRouterProvider>
}
```

Then wrap the app with it in the root layout:

```tsx
// app/layout.tsx
import 'rudiment-ui/styles'
import './globals.css'
import { Providers } from './providers'

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <Providers>{children}</Providers>
      </body>
    </html>
  )
}
```

The pages it wraps can stay Server Components.

## Icons

Components take Iconify names such as `icon="mdi:close"`. The icons the components use themselves are part of the package. Iconify downloads any other icon from `api.iconify.design` in the browser the first time it renders, and the server HTML holds an empty `span` in its place.

To bundle the app's icons, install the icon set for each prefix, then write the icons the app uses to a JSON file.

```bash
npm install -D @iconify-json/mdi
npx rudiment-ui-icons app --out app/rudiment-icons.json
```

`registerRudiIcons` comes from a `'use client'` module, so a Server Component can't call it. Call it in a client file and render that file's component in the root layout. The module then runs on the server and in the browser before any page renders.

```tsx
// app/icons.tsx
'use client'
import { registerRudiIcons } from 'rudiment-ui'
import icons from './rudiment-icons.json'

registerRudiIcons(icons)

export function RudiIcons() {
  return null
}
```

```tsx
// app/layout.tsx
import { RudiIcons } from './icons'

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <RudiIcons />
        {children}
      </body>
    </html>
  )
}
```

If the app has `app/providers.tsx` from step 6, call `registerRudiIcons(icons)` at the top of that file instead. It's already a client file that the root layout renders.

Run `rudiment-ui-icons` again after adding an icon. If your app sets a Content Security Policy and some icons still load from the API, allow `api.iconify.design` in `connect-src`. The [Performance](?path=/docs/getting-started-guides-performance--docs) page covers the command's options.
